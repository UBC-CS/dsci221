The Problem

Your genome has 3 billion base pairs — a sequence of A, T, G, C.

No machine can read it all at once.

Instead: shred many copies of the genome into millions of short fragments, read each fragment, and reassemble.

This is called shotgun sequencing.

Shotgun sequencing is the dominant method since the Human Genome Project (2003). The “shotgun” metaphor: randomly blast the genome into tiny pieces, then figure out how they fit back together from the overlaps.

The Fragments Arrive as Data

Each fragment is a short string of bases — a k-mer.

For a toy genome and k=3:

import pandas as pd

genome = "ATGCAT"   # pretend it's circular
k = 3

kmers = [genome[i:i+k] for i in range(len(genome))]
df = pd.DataFrame({'kmer': kmers})
   kmer
0   ATG
1   TGC
2   GCA
3   CAT

In real sequencing: millions of rows, k ≈ 100–300.

The genome is circular in many organisms (bacteria especially). For simplicity we start with a circular example — it produces an Euler circuit rather than a path, which is the cleanest case.

Can You Reassemble It?

Given only this bag of 3-mers — no positions, no order:

ATG    TGC    GCA    CAT

Can you recover the original sequence?

Try it. What do you notice about the fragments?

Give students 30 seconds. They’ll notice each fragment overlaps with the next by k-1 = 2 characters. ATG ends in TG, TGC starts with TG. And so on. This overlap structure is the key.

The Overlap Structure

Each k-mer overlaps its neighbours by k−1 characters.

ATG
 TGC
  GCA
   CAT
    AT...

The fragments chain together. But with millions of fragments — many of them identical — you can’t just line them up by eye.

We need a systematic approach.

Naïve Idea: Overlap Graph

Draw a node for each fragment. Draw an edge when two fragments overlap.

ATG ──► TGC ──► GCA ──► CAT ──► ATG ...

This works! But checking every pair of fragments for overlap costs \(O(n^2)\) comparisons. For millions of fragments, that’s trillions of checks.

We need a smarter graph.

A Different Graph

Instead of nodes = k-mers, let nodes = (k−1)-mers and edges = k-mers.

k-mer prefix (k−1) suffix (k−1) edge
ATG AT TG AT → TG
TGC TG GC TG → GC
GCA GC CA GC → CA
CAT CA AT CA → AT

Each fragment becomes an edge between its prefix and suffix.

This is the de Bruijn graph construction. Named after Nicolaas de Bruijn. The key insight: the overlap structure is captured by the shared (k-1)-mer between consecutive edges.

The de Bruijn Graph

k-mer edge
ATG AT → TG
TGC TG → GC
GCA GC → CA
CAT CA → AT

Nodes are 2-mers. Edges are 3-mers (our reads).

The genome is hidden in this graph — but how do we read it out?

What Does Traversal Mean Here?

Assembling the genome = spelling out all four reads in order.

That means visiting every edge exactly once.

What kind of graph traversal visits every edge exactly once?

Euler’s Circuit

An Euler circuit visits every edge exactly once.

Leonhard Euler, 1736 — the Königsberg bridge problem.

Genome assembly is finding an Euler circuit in the de Bruijn graph.

Euler proved in 1736 that the Königsberg bridge problem (can you cross each of 7 bridges exactly once?) had no solution, by analysing the degree of each landmass. That paper is widely considered the birth of graph theory. 290 years later, the same idea assembles genomes.

When Does an Euler Circuit Exist?

Euler’s theorem: A connected directed graph has an Euler circuit if and only if every node has equal in-degree and out-degree.

Check our graph:

Node Out In Balanced?
AT 1 1 ✓
TG 1 1 ✓
GC 1 1 ✓
CA 1 1 ✓

Assembly is possible.

For a linear genome (Euler PATH rather than circuit): exactly one node has out − in = 1 (start), exactly one has in − out = 1 (end), all others balanced. Real genomes are linear, so we look for an Euler path. Checking degrees tells you immediately whether assembly is even possible — before you run any algorithm.

Euler Path vs. Euler Circuit

Circuit Path
Start = End? Yes No
Degree condition All nodes balanced Exactly two unbalanced nodes
Genome type Circular (bacteria) Linear (humans)

For a linear genome: find the unique node with \(\text{out} - \text{in} = 1\). That’s your start.

This is a beautiful pre-check: before running any algorithm, just compute in-degrees and out-degrees. O(E). If the condition fails, assembly from these reads is impossible (there are gaps or errors in your data).

From Euler to Code

We know DFS from week 6. Here is the classic version:

def dfs(graph, v, visited, path):
    visited.add(v)
    path.append(v)          # pre-order: record on arrival
    for w in graph[v]:
        if w not in visited:
            dfs(graph, w, visited, path)

This visits each node once. We need to visit each edge once.

Two things must change — and the second one is subtle.

Don’t reveal the answer yet — this is the bridge to the code task. The two changes: 1. Track consumed edges (pop from adjacency list) instead of visited nodes 2. Move path.append to AFTER recursion (post-order) The second change is what makes the “splicing” work.
