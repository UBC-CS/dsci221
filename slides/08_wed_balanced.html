The Big Idea

Can we automatically rebalance the tree after insertions?

Yes! Several self-balancing tree structures exist:

  • AVL trees (1962): First balanced BST
  • Red-Black trees (1978): Used in most standard libraries
  • B-trees (1970): Used in databases and file systems

Today: The concept of balance, using AVL trees as our example.

What Does “Balanced” Mean?

Intuition: Left and right subtrees should be “about the same size.”

Height balance: The heights of left and right subtrees differ by at most 1.

Balance factor of a node: \[b = \text{height}(\text{right}) - \text{height}(\text{left})\]

A tree is AVL-balanced if every node has \(b \in \{-1, 0, 1\}\).

AVL Trees

Named after inventors Adelson-Velsky and Landis (1962).

AVL Property: For every node, the heights of left and right subtrees differ by at most 1.

This guarantees O(log n) height!

Checking Balance

Every node has balance factor -1, 0, or 1. ✓ AVL-balanced!

An Unbalanced Tree

Balance factor > 1 or < -1? Not AVL-balanced!

Why AVL Balance Guarantees O(log n)

Theorem: An AVL tree with n nodes has height O(log n).

Intuition: If subtrees differ by at most 1, the tree can’t be too “stringy.”

Proof idea: The minimum number of nodes in an AVL tree of height h is: \[N(h) = N(h-1) + N(h-2) + 1\]

This grows exponentially (like Fibonacci), so \(h = O(\log n)\).

The Magic: Rotations

When an insertion makes a node unbalanced, we rotate to restore balance.

A rotation:

  • Rearranges a few nodes
  • Maintains the BST property
  • Reduces height of the subtree
  • Takes O(1) time

Double Rotations

Sometimes a single rotation isn’t enough.

Left-Right case: Left child is right-heavy

  1. Rotate left on the child
  2. Rotate right on the node

Right-Left case: Right child is left-heavy

  1. Rotate right on the child
  2. Rotate left on the node

The AVL Insert Algorithm (Conceptual)

def avl_insert(tree, key):
    1. Do standard BST insert (key becomes a leaf)
    2. Walk back up to the root, checking balance
    3. If any node has balance factor ±2:
       - Determine which case (left-left, left-right, etc.)
       - Apply appropriate rotation(s)
       - Update heights
    4. Return the (possibly new) root

At most one rotation (single or double) is needed per insert!

The Key Insight

We don’t need to implement rotations ourselves.

What you need to know:

  1. Unbalanced BSTs can have O(n) height
  2. AVL (and similar) trees maintain balance via rotations
  3. This guarantees O(log n) operations
  4. Most languages provide balanced tree implementations

Summary: Balanced Trees

  1. BST operations are O(height) — height matters!

  2. Unbalanced BSTs can have O(n) height — bad for sorted input

  3. AVL trees maintain balance via rotations after insert/delete

  4. AVL property: heights of subtrees differ by ≤ 1

  5. Guarantee: O(log n) height, so O(log n) operations

  6. In practice: Use library implementations (Red-Black, B-trees)

The Trade-off

Structure Insert Find Sorted?
Hash table O(1) avg O(1) avg No
Balanced BST O(log n) O(log n) Yes

Hash tables win on speed. Trees win on ordering.

Choose based on your needs!
