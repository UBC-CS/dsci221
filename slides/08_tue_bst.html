Perfect Binary Trees

A perfect binary tree has all levels completely filled.

Nodes at height h: \(2^{h+1} - 1\)

Flip it around: A tree with n nodes has height at least \(\log_2(n+1) - 1\).

This is \(\Omega(\log n)\) — height grows logarithmically with nodes.

Why Height Matters

Many tree operations take time proportional to height:

  • Finding a node
  • Inserting a node
  • Deleting a node

If height is \(O(\log n)\): these are fast (\(O(\log n)\))

If height is \(O(n)\): these are slow (\(O(n)\))

Goal: Keep trees balanced so height stays logarithmic!

Back to Wordle

Remember our decision tree?

  • Height = worst-case guesses
  • Good first guess = tree with minimum height
  • Best guesses split possibilities evenly

This is a general pattern: decision trees model any sequence of choices where each choice narrows down possibilities.

The Dictionary Problem

We want to store key-value pairs with fast operations:

  • insert(key, value): Add a new entry
  • find(key): Look up a value by key
  • remove(key): Delete an entry

Python’s dict does this in O(1) expected time using hashing.

Can we do it with a tree?

Why Trees Instead of Hash Tables?

Hash tables give O(1) expected time. Why use trees?

Trees can do things hash tables can’t:

  • Sorted iteration: Traverse keys in order
  • Range queries: Find all keys between A and B
  • Predecessor/successor: Find the next-smallest key
  • No hash function needed: Works with any comparable type

The Binary Search Tree Property

A Binary Search Tree (BST) is a binary tree where:

For every node with key k:

  • All keys in the left subtree are < k
  • All keys in the right subtree are > k

This property holds for every node, not just the root!

BST Example

Or define a simple node class for clarity.

A Simple Node Representation

def node(key, left=None, right=None):
    """Create a BST node as a dictionary."""
    return {'key': key, 'left': left, 'right': right}

# Build the tree
tree = node(38,
    left=node(13,
        left=node(10),
        right=node(25, left=node(12))),
    right=node(51,
        left=node(40),
        right=node(84)))

Finding a Key

To find a key in a BST:

  1. Start at the root
  2. If key == current node’s key: found it!
  3. If key < current node’s key: go left
  4. If key > current node’s key: go right
  5. If we reach None: not found

This is binary search on a tree structure!

BST Find Implementation

def bst_find(tree, key):
    """Find a key in a BST. Returns the node or None."""
    if tree is None:
        return None

    if key == tree['key']:
        return tree
    elif key < tree['key']:
        return bst_find(tree['left'], key)
    else:
        return bst_find(tree['right'], key)

Running time: O(height of tree)

Tracing a Find

Find 25 in the tree:

38 → 25 < 38, go left
13 → 25 > 13, go right
25 → Found!

Only 3 comparisons for a tree of 8 nodes!

Finding the Minimum

The smallest key is always in the leftmost node:

def bst_min(tree):
    """Find the minimum key in a BST."""
    if tree is None:
        return None

    if tree['left'] is None:
        return tree['key']

    return bst_min(tree['left'])

(Similarly, maximum is the rightmost node.)

Inserting a Key

To insert a new key:

  1. Search for where it would go
  2. When you reach None, create a new node there

The new node is always inserted as a leaf.

BST Insert Implementation

def bst_insert(tree, key):
    """Insert a key into a BST. Returns the new tree."""
    if tree is None:
        return node(key)

    if key < tree['key']:
        tree['left'] = bst_insert(tree['left'], key)
    elif key > tree['key']:
        tree['right'] = bst_insert(tree['right'], key)
    # If key == tree['key'], it's a duplicate; do nothing

    return tree

Running time: O(height)

Building a BST

def build_bst(keys):
    """Build a BST from a list of keys."""
    tree = None
    for key in keys:
        tree = bst_insert(tree, key)
    return tree

# Build from keys
tree = build_bst([38, 13, 51, 10, 25, 40, 84])

The Height Problem

Tree Shape Height Find/Insert Time
Balanced O(log n) O(log n)
Degenerate (list) O(n) O(n)

Worst case: If we insert sorted data, BST degenerates to a list.

Solution: Keep the tree balanced (Wednesday’s topic!)

Inorder Traversal: Sorted Output!

Remember inorder traversal? Left, root, right.

For a BST, this visits keys in sorted order:

def inorder(tree):
    if tree is None:
        return []
    return (inorder(tree['left']) +
            [tree['key']] +
            inorder(tree['right']))

# Returns: [10, 12, 13, 25, 38, 40, 51, 84]

This is why BSTs support sorted iteration!

Why Inorder Gives Sorted Order

The BST property guarantees:

  • Everything in left subtree < root < everything in right subtree

Inorder visits left (smaller keys), then root, then right (larger keys).

So we get keys in ascending order!

BST: Delete a Key

Deletion is trickier. Three cases:

  1. Leaf node: Just remove it
  2. One child: Replace node with its child
  3. Two children: Find successor, swap, delete successor

We won’t implement this in detail, but the idea is straightforward.

BST is a good all-rounder when you need sorted access.

Python’s Relationship to BSTs

Python’s dict uses hash tables, not BSTs.

But BST concepts appear in:

  • bisect module (binary search on sorted lists)
  • Database indexes (B-trees, a generalization)
  • sortedcontainers library (3rd party)
  • Red-black trees in many languages’ standard libraries

Summary: Binary Search Trees

  • BST property: left < root < right (recursively)
  • Find: Binary search down the tree
  • Insert: Find where it belongs, add as leaf
  • Inorder traversal: Gives sorted order
  • Running time: O(height)
  • Problem: Height can be O(n) in worst case
